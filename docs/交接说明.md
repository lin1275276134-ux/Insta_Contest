## 已实测事实及重要陷阱

- X5 固件响应：`A3_1.11.6.523_build1`。本机 Darwin 25.5.0、arm64，Python 3.14.6。
  MCU v1.2.5 来自既有用户信息，本轮未独立读取。
- Mac 连接相机 Wi-Fi 后访问 `http://192.168.42.1`；info/state 成功。
  请求带 `Content-Type: application/json;charset=utf-8`、`Accept`、`X-XSRF-Protected: 1`。
- `camera.listFiles` 实测接受 `fileType=video`、`startPosition`、`entryCount`、`maxThumbSize=null`。
  请求 20 条时实际每页最多 15 条，`totalEntries` 是该页数量，不能当整卡总数。
  必须按实际返回数量推进偏移、继续短页并读至空页，还需复扫对账。不能假定最新在第一页。
- 077 出现时旧基线只有第一页，不计严格新增成功。078：106→108；079：108→110；
  两次均复扫稳定、旧条目不变，严格按钮录制发现目前只有 2 段，且模式不同；未达到 HW02 连续至少 5 段。
- 078 是双鱼眼全景路径：INSV 两路 1920×1920 HEVC，LRV 抽帧也是双鱼眼。G1 此路径未过。
- 079 是单镜头普通录像：原 MP4 1920×1080 HEVC、约 29.97fps、12.345667 秒。
  用户选择模式后人工抽帧确认普通视角，现有 prepare 生成等时长 H.264 副本，原片/副本全片解码通过。
- 目录 width/height 对不同片段仍返回 6080×3040，`isProcessed=true` 也不能证明已拼接。
  不要根据文件后缀、目录尺寸或 isProcessed 判定投影。
- MP4 与同次 LRV 是原片/预览关系，不能一起作为连续分段传给 prepare，否则会重复计算时长。
- 大小稳定和下载字节数一致只是部分证据，不等于录制结束、完整文件组或长期可靠就绪信号。

## 代码与证据入口

- `tools/probes/inspect_device.py`：只读 info/state、ffprobe 与 SHA-256；不覆盖旧报告。
- `tools/probes/catalog_probe.py`：固定设备地址，最多 100 页、逐请求超时 8 秒，防重复条目。
  报告始终保持 completeness=unverified；需检查 termination，只有 empty_page 表示读到空页。
  **脚本当前遇请求失败仍可能退出 0，不能只看退出码，也不能直接作为生产 worker。**
- `tests/unit/test_probe.py`、`tests/unit/test_catalog_probe.py`：新增 5 项回归。
- `backend/app/service.py`、`backend/app/jobs/worker.py`：检查现有相机/模型构造、扫描与下载调用，替换前先定义边界。
- `backend/app/camera/simulator.py`、`backend/app/analysis/simulator.py`：现有假实现。
- `backend/app/media/service.py`：现有真实 FFmpeg prepare；投影输入需可信判定。
- [详细探测记录](device-probe.md) 与 [已入库脱敏证据](evidence/2026-09-22/README.md)。

下载和目录差异比较本轮由临时 Python 命令执行，并未实现成可复用生产下载器；不要误判为 T03 完成。
