# 开发测试与验收流程 v1.0

> 当前进度请先读 [2026-09-22 冻结交接](交接说明.md)。本文件下方的“本轮未实现/未测试”等措辞描述最初设计阶段；任务要求仍有效，实际完成情况以交接与实测记录为准。

> 本文件定义待实现、待执行的测试流程。当前没有产品代码或测试通过结果。配套：[主计划](../开发计划_初稿.md)、[架构接口](架构与接口设计.md)。

## 1. 开发顺序：先暴露失败，再实现，再集成

每张任务卡采用以下循环：

1. 读取上游契约，确认输入、输出、不变量和失败恢复。
2. 为真实风险编写最小失败用例，例如「扫描第二页失败不能提交完整基线」；确认该测试能识别错误实现，不写只照抄实现逻辑的测试。
3. 实现最小模块，使用临时数据库、隔离文件目录和假设备/假模型。
4. 跑相关单元与集成测试，再跑类型检查及构建；修复失败并保留记录。
5. 与上游/下游联调，对比真实 API 与契约；接口变动更新共享 Schema 和 fixtures。
6. 交付任务卡结果：改动、命令、用例 ID、运行环境、通过/失败/未运行及原因。

真正的设备、模型调用和性能只在 live 层验证。离线 CI 不使用真实密钥，不对连接着的相机自动发起录制或删除操作。

## 2. 测试环境和可重复输入

| 层次 | 使用工具建议 | 证明什么 |
|---|---|---|
| 单元 | pytest、前端测试框架 | 去重、归属、覆盖规则、状态转移、Schema |
| 服务集成 | pytest + HTTP 客户端、临时 SQLite/文件目录、可控假 HTTP 相机 | 请求契约、任务事务、分页、故障恢复 |
| 浏览器 E2E | Playwright，真实本地 API + 假设备/模型 | 用户完整操作及状态展示 |
| 媒体实测 | ffprobe/FFmpeg + 团队提供视频 | 格式、可播放性、分段/时间/视角映射 |
| 模型评估 | 固定标注集 + 真实模型 | 观察、匹配、遮挡判断与证据定位质量 |
| 真机 | 实际 Mac + X5 + 真实模型 | 相机本身录制→发现→导入→建议整个链路 |

测试 fixtures 至少包含：

- 相机目录按时间推进的序列：多页、重复项、乱序、录制中增长、成员迟到、换卡/同名覆盖、分页失败、重连补扫。
- 同一教程的素材：材料、成品、缺关键动作、动作被遮挡、合格补拍、无关片段、一段覆盖多个分镜、多段覆盖一个分镜。
- 模型结果：支持、明确缺陷、不确定、越界时间、错误项目 ID、缺字段、超时、无效 JSON、重复响应。
- 标注 manifest：样本 ID、文件 hash、所属集合、分镜/criterion 真值、可接受证据时间窗、遮挡原因、是否可判定完成。

将调试集与冻结验收集分开，建议各至少 6 个短片且覆盖关键类别，条件不足时记录缺少的覆盖项。不得把同一源视频裁成两个高度重复片段后声称独立验证。样本与响应不含凭据；大视频不直接塞进 Git，保留位置与 hash。

## 3. 核心用例矩阵

### SY：扫描、归属与下载

| ID | 输入/操作 | 断言 |
|---|---|---|
| SY01 | 首次扫描 3 页，用户只选 2 组 | 未选历史组不入队，以后扫描也不当作新增 |
| SY02 | 第二页请求失败/页间新增 | 基线不被错误提交；复扫对账后无遗漏 |
| SY03 | 用户选择范围期间拍出新组 | 新组待确认，不悄悄扩大原选择 |
| SY04 | 连续 10 次相同目录 | 每组只有一个有效导入/分析任务，模型调用计数不增加 |
| SY05 | 文件大小增长/组成员迟到 | awaiting_ready；不能下载半组后标 analyzed |
| SY06 | 录制停止后完整新组出现 | 在同步允许的下次扫描周期发现并入队；未就绪前不处理 |
| SY07 | 下载中断、字节不足、远端版本变化 | 不晋升正式副本，重试不重复导入 |
| SY08 | 同名不同内容、疑似换卡、时钟回退 | 不误复用旧结果；疑似存储变化要求重新确认 |
| SY09 | 暂停/断连后拍摄，随后重连 | 已有记录保留，离线新增组待确认，确认后无漏导 |
| SY10 | 项目 A 同步时启动项目 B | 拒绝抢占或先显式关闭 A；素材和任务不跨项目 |

### ME：媒体

| ID | 输入/操作 | 断言 |
|---|---|---|
| ME01 | 实际支持模式的完整文件组 | 原片保留，生成可播放副本并正确关联来源 |
| ME02 | 损坏/截断视频或缺少文件组成员 | 失败或等待，不产生可计入覆盖的证据 |
| ME03 | 未处理 INSV/双鱼眼/未知投影 | blocked_format，明确处理需求，不伪装普通视频 |
| ME04 | 长片分段、不同帧率、时间偏移 | 总输入覆盖完整，无静默截断，证据可定位回正确片段；时间误差建议不超过 1 秒 |
| ME05 | 磁盘满、转码中断、源文件超限 | 明确失败且可恢复；已有素材不损坏、进度不虚增 |

### AI：模型与匹配

| ID | 输入/操作 | 断言 |
|---|---|---|
| AI01 | 教程目标→清单 | 准备、必要动作、结果及通过标准可观察；空清单不能确认 |
| AI02 | 缺关键动作/明显遮挡/清楚补拍 | 正确区分 pending/reshoot/covered，记录误判 |
| AI03 | 视觉含糊、关键动作短暂 | 不凭前后画面猜测连续动作，无法确认进入 uncertain |
| AI04 | 一片多分镜/多片一分镜 | 候选关联不强制一一对应，连续 criterion 仍满足约束 |
| AI05 | 错误 ID/越界时间/无效结构 | 拒绝结果，不产生支持证据，错误可定位 |
| AI06 | 超时、重试、旧版本延迟结果 | 保留旧有效状态，有限重试，过期结果不提交 |

### RU：规则与建议

| ID | 输入/操作 | 断言 |
|---|---|---|
| RU01 | 空/未确认/部分覆盖清单 | 不显示 ready |
| RU02 | 已有合格证据再导入差片 | 原 covered 不被推翻，下一建议不要求重拍已满足项 |
| RU03 | 必要标准都被覆盖、扫描清洁且新鲜 | ready，包含逐项证据和 checked_at |
| RU04 | 覆盖齐全但有分析失败/未就绪片 | checking，直至重试完成或明确排除 |
| RU05 | 覆盖齐全但断连/暂停/扫描过期 | unverified，保留覆盖进度，不声称检查了最新素材 |
| RU06 | 排除唯一合格素材/本地证据丢失 | 相关证据失效并回退覆盖；相机远端删除但本地仍在不回退 |
| RU07 | 重复提交、重试旧 attempt、计划/素材版本变化 | 幂等生效，旧结果不能覆盖当前结果 |
| RU08 | 多个缺口、模型润色失败 | 优先建议必要缺口；拍什么/怎么拍/为什么齐全，模板可用 |

### UI：使用界面

| ID | 操作 | 断言 |
|---|---|---|
| UI01 | 首次进入→建项目→确认分镜→选范围 | 步骤可完成，不能绕过必需确认 |
| UI02 | 下载、分析、断连和格式失败 | 分别显示阶段及恢复动作，不混成「分析失败」 |
| UI03 | 点击分镜证据 | 正确副本从证据时间点播放 |
| UI04 | 刷新页面/重启后端 | 项目与证据恢复，任务不永久卡 running |
| UI05 | 新快照先到、旧快照后到 | 界面保留新 revision；freshness 超时仍正确变化 |
| UI06 | 误收素材排除、暂停、恢复 | 可操作且后端状态一致；模拟环境明确标识，无相机录制控制 |

## 4. E2E 场景与恢复测试

- **E01 标准闭环：**初始目录含其他项目素材及材料/成品。只选本项目素材→显示关键步骤缺口→假相机新增遮挡片→建议补拍→新增清楚片→清洁扫描后 ready。检查全程模型调用数、证据和数据库关联。
- **E02 故障闭环：**新增组写入中→下载断网→恢复→模型外网失败→恢复→分析成功；任一中间阶段不能新增完成计数，最终每组只保留一份有效导入。
- **E03 持久恢复：**分别在下载、转码、模型返回后提交前终止 worker，再启动；临时文件和租约可恢复，旧尝试不会覆盖新结果。
- **E04 项目边界：**暂停项目 A，拍出 B 的片段；打开 B 并选择归属；A 不会因重连自动吸收 B 的素材。
- **E05 完成撤回：**ready 后新增片段进入 checking；排除唯一合格素材后 not_ready；保留旧历史但展示当前结论。

检查本地接口边界：非法路径/跨项目素材引用/外部下载目标/重复幂等键不同 payload 被拒绝；密钥不出现在 health、快照或日志。无需为纯文案和低风险样式变化新增镜像测试。

## 5. HW：X5 真机前置验证

这组测试不能用假设备替代，报告需注明设备固件、Mac 芯片/系统、拍摄模式、网络方式、真实协议请求和时间。

| ID | 操作 | 通过标准 |
|---|---|---|
| HW01 | 浏览已有视频，数量超过一页 | 实際枚举全部视频组，分页不漏项；无支持时明确失败 |
| HW02 | 用户按相机按钮录制并结束，连续至少 5 段 | 软件无需开始/停止录制指令即可发现新增组；没有漏片 |
| HW03 | 在录制中扫描及尝试允许的读取 | 记录真实支持范围，不能影响录制或读到半文件后误判就绪 |
| HW04 | 下载指定模式素材并制备副本 | G1 通过，证据播放器和模型使用同一可用内容 |
| HW05 | 相机 Wi-Fi 与模型联网 | 记录能否同时使用；若需切网，下载/队列恢复可用且限制写入文档 |
| HW06 | 断连后在相机录制再重连 | 补扫找到全部新增组，先确认归属，历史不重复处理 |

如果 HW01/HW02 失败，即便网页和 AI 流程工作正常，仍不能认定本产品核心完成。导出再手动上传只能作为后端能力测试。实现者应提交失败证据与路线变更建议，等待产品范围决策。

## 6. 模型质量与性能记录

模型错误和程序错误分开统计：

- 必要项覆盖误报数：未拍齐或不可用却被标 covered/ready 的数量；冻结验收场景中必须为 0。
- 需补拍漏检数、不确定判断数、正确分镜关联数；报告分母和具体样本，不能只报百分比。
- 证据定位：每个 covered 项的时间窗是否指向实际动作，是否满足连续性；全部必要 covered 项人工核对。
- 建议可执行性：每条是否明确内容、方法、理由，是否对应当前缺口。

每个 live 运行记录：`record_end_at`、`first_seen_at`、`ready_at`、下载/媒体/模型耗时、总耗时、输入字节数、输入长度、调用次数、供应商用量与可取得的费用。设备结束时间与 Mac 时钟不同步时，明确校准方式，不能直接相减。

性能暂不承诺固定秒数。T00/T05 后填写项目接受的最大发现延迟、分析等待和成本预算，再作为 T09 出口。模拟器中可断言一次扫描间隔内发现；实际总耗时包含录像落盘、Wi-Fi 和模型服务。样本少时报告每次值和最大值，不用虚假的 P95。

建议队列模拟压测使用 50 个轻量组验证不漏项、去重、分页与背压；这不代表 50 个真实大视频的处理性能。缓存和重启测试确认未变片段不重复调用模型。

## 7. 每阶段出口与测试命令契约

以下脚本路径是要求 T01/T10 实现的统一入口，目前并不存在，不是本轮已经执行的命令：

| 入口 | 应完成的工作 |
|---|---|
| `scripts/check` | 后端静态检查/单元测试、前端类型检查/相关单元测试、构建；不联网调用模型 |
| `scripts/test-integration` | 临时库与假相机/假模型的服务测试，退出后清理测试目录 |
| `scripts/test-e2e` | 启动隔离服务与浏览器 E2E，保留失败截图和日志 |
| `scripts/test-live` | 明确指定设备 profile、项目与样本集，运行真机/真实模型验证并记录用量；不能由普通 CI 自动触发 |
| `scripts/dev` | 开发启动，模拟开关显式配置 |
| `scripts/start` / `scripts/stop` | 正式本地启动/停止，优雅结束 worker、保留任务与数据 |

合并门槛：相关单元/集成检查通过，Schema 与调用方一致，核心链路改动跑 E2E；真实适配器改动还需相应 HW 用例。修复一个失败先运行该用例，再运行依赖回归，不无故反复全量调用收费模型。

阶段出口：

1. T00：硬件能力表有证据，失败项不伪装已支持。
2. T01：Schema 与模拟器可运行，定义清晰错误语义。
3. 模块交付：对应 SY/ME/AI/RU/UI 用例通过，依赖未具备则标未运行。
4. T08：E01—E05 通过，进程/网络恢复可复现。
5. T09：HW 用例和真实模型验收通过，必要项误报为 0，性能在已约定预算内。
6. T10：另一位使用者独立安装使用成功，最终报告包括运行平台与限制。

## 8. 缺陷处理与最终交付记录

缺陷记录字段：ID、关联任务/用例、版本、复现步骤、预期/实际、日志或状态快照、严重度、修复版本、回归结果。错误完成判断、漏导新素材、跨项目归属、持久数据损坏为阻断交付的问题；其余影响是否可接受需明确记录。

```text
软件版本 / commit：
Mac 系统与芯片：
X5 固件 / 拍摄模式 / 连接方式：
```

软件交付还应包含完整使用指南：首次配置模型、连接 X5、确认分镜、选择历史范围、现场自动同步、看补拍建议与证据、暂停/重连归属确认、失败恢复、结束项目及本地数据清理。当前文档规定该指南的验收内容，具体安装命令须由真实实现验证后填写。
